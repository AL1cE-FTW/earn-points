# earn-points — バスツアー会員ポイント制度

バスツアーの旅行客に付与する、会員向けポイント制度とその管理システムです。ツアーに参加するとポイントがたまり、次のツアー代金に1ポイント1円で使えます。

LINE などの外部サービスには頼らず、自社の中だけで運用できるように作っています（詳しくは「[外部サービスについて](#外部サービスについて)」）。

## このリポジトリの中身

同じ制度を、目的の違う2つの形で実装しています。

| | 画面デモ（`site/`） | サーバ版（`points/`） |
|---|---|---|
| 目的 | 制度の紹介と、画面の見た目・操作感の確認 | 実際の窓口での運用 |
| 動く場所 | ブラウザだけ（GitHub Pages で公開） | 事務所の PC など（Python で起動） |
| データの保存先 | 見ている人のブラウザ（localStorage） | SQLite ファイル1つ |
| 端末間のデータ共有 | できない | できる（同じサーバに接続） |
| 画面のデザイン | 白地と緑の、業務画面に近いデザイン | 初期の簡易デザイン（緑） |

```
site/                    画面デモ（GitHub Pages で公開）
  index.html             制度のご案内（トップ）
  member/index.html      会員ページ
  admin/index.html       スタッフ画面
  points.js              制度の計算ロジック（ブラウザ版）
  assets/ui.css          共通デザイン（色・書体・部品）
  assets/viewswitch.js   PC での「PC表示／スマホ表示」切り替え
  michi/                 提案版（招待制「道ツアー」入り）。3画面のコピーと追加ロジック michi.js
points/                  サーバ版（Python 標準ライブラリ + SQLite）
  rules.py               制度の数値（付与率・ランク・有効期限など）
  service.py             入会・付与・利用・取消・失効・退会の処理

.github/workflows/pages.yml  site/ を GitHub Pages へ公開する設定
```

## 制度の概要

| 項目 | 内容 |
|---|---|
| 入会特典 | 300pt |
| ツアー参加 | 支払額（ポイント利用分を除く税込代金）100円ごとに1pt × ランク倍率 × キャンペーン倍率 ＋ キャンペーン加算 |
| 誕生月特典 | 出発日が誕生月なら +200pt |
| ご紹介特典 | 紹介した方の初参加時に、紹介者へ 500pt |
| 会員ランク | 出発日より前の1年間の参加回数で判定：レギュラー（×1）／シルバー 3回〜（×1.5）／ゴールド 6回〜（×2） |
| 利用 | 100pt単位、1pt＝1円でツアー代金に充当（代金が上限） |
| 有効期限 | 付与日から2年後の月末。期限の近いポイントから消費 |
| 取消・中止 | 使ったポイントは元の有効期限のまま返還 |
| 退会 | 保有ポイントは失効 |

> 上記の数値は、一般的なポイント制度を参考にした**初期案**です（特定の調査や他社事例を出典とするものではありません）。利益率に合わせて調整してください。

会員向けの規約ひな形と、景品表示法・資金決済法まわりの確認メモは [`docs/ポイント規約.md`](docs/ポイント規約.md) にあります。法令メモは施行前に専門家の確認が必要です。

### 数値を変えるとき

制度の数値は2か所にあります。**両方を同じ値に直してください。**

- サーバ版：[`points/rules.py`](points/rules.py)
- 画面デモ：[`site/points.js`](site/points.js) の `RULES`

トップページの説明文（`site/index.html` の「ため方」「ランク」など）にも数値を書いているので、あわせて直します。

## 画面デモ（`site/`）

### 画面

- **制度のご案内（トップ）**：ため方、付与ポイントの計算機（代金とランクを選ぶと付くポイントと計算式が出る）、ランク、使い方と有効期限、よくある質問
- **会員ページ**：会員証、保有ポイントと有効期限の内訳、ランクの進み具合、次のツアー、ポイント履歴、ツアー一覧、暗証番号の変更。PC は左にメニュー、スマホは画面下のタブ
- **スタッフ画面**：ホーム（未使用ポイント残高・失効予定・次の出発の集計）、会員検索と詳細、新規入会、ツアー登録、予約とポイント利用、催行完了での一括付与、取消・中止、ポイント調整、退会、失効処理。デモの日付は画面上部の帯で変更。PC は左にメニュー、スマホは上に横並びのメニュー

同じブラウザなら、スタッフ画面で行った予約やポイント付与が、会員ページにすぐ反映されます。

### 手元の PC で見る

```sh
python3 -m http.server 8080 -d site
```

ブラウザで http://127.0.0.1:8080/ を開きます。`index.html` を直接ダブルクリックで開くと、ページ間のデータ共有などが正しく動かない場合があるため、この方法をおすすめします。

### 公開の仕組み

`main` ブランチの `site/` が変わると、GitHub Actions（[`.github/workflows/pages.yml`](.github/workflows/pages.yml)）が自動で GitHub Pages に公開します。

最初の1回だけ、リポジトリの **Settings → Pages → Build and deployment の Source を「GitHub Actions」** にする必要があります（設定済み）。

### デザイン

- 旅行会社の窓口で配る案内や、業務用の画面に近い、飾りの少ない見た目にしています。
- 色は白地とブランド色（緑）1色、グレーだけです。ポイント数だけ橙で強調します。ライト・ダークの両方に対応しています。
- 角丸は小さく、影・グラデーション・動きは使いません。情報は表で区切ります。
- 見出しや説明はすべて日本語です。ご年配の会員も読みやすいよう、文字は大きめにしています。
- 書体は端末に入っているゴシック体だけを使います。
- 色・書体・部品は [`site/assets/ui.css`](site/assets/ui.css) にまとめています。ブランド色を変えるときは、ここの `--brand` と `--bar` を直します。

## サーバ版（`points/`）

Python 3 の標準ライブラリだけで動きます（Python 3.11 で動作確認）。`pip install` は不要です。データは SQLite ファイル1つ（既定は `points.sqlite3`）に保存されます。

### 起動

```sh
python3 -m points demo     # （任意）サンプル会員・ツアーを投入
python3 -m points serve    # 画面を起動 → http://127.0.0.1:8000/
```

- 会員ページ：`http://127.0.0.1:8000/`（会員番号と暗証番号でログイン）
- スタッフ画面：`http://127.0.0.1:8000/admin`
  初回起動時に管理パスワードが表示されます。環境変数 `POINTS_ADMIN_PASSWORD` で指定するか、`python3 -m points passwd` で変更できます。
- 社内 LAN のほかの端末から使う場合は `--host 0.0.0.0` を付けます。インターネットへ公開する場合は、HTTPS 化（リバースプロキシなど）を必ず行ってください。
- 主なオプション：`--db ファイル名`（環境変数 `POINTS_DB` でも可）、`--port 番号`

### 日々の運用

1. **入会**：「新規入会」で登録し、会員証を印刷してお渡しします（暗証番号はお客様に決めてもらう）。
2. **ツアー登録**：「ツアー」でツアーコード・出発日・代金・キャンペーン倍率を登録します。
3. **予約**：ツアー画面で会員番号を入れて残高を確認し、使うポイントを入力して予約を登録します。
4. **催行完了**：出発日以降、ツアー画面で不参加の方にチェックを付けて「催行完了として付与」を押します。
5. **取消・中止**：予約ごとの「取消」または「ツアーを中止」で、使ったポイントが自動で戻ります。
6. **失効処理**：残高の表示は期限切れを自動で除きますが、台帳に失効の記録を残すため、毎日 `python3 -m points expire` を cron などで実行してください（管理トップのボタンでも可）。

### バックアップ

データは SQLite ファイル1つです。サーバを止めてコピーするか、動かしたままなら `sqlite3 points.sqlite3 ".backup backup.sqlite3"` で取得できます。

### 設計メモ

- ポイントの増減はすべて取引台帳 `point_txns` に記録します。有効期限を管理するため、付与ごとの残高 `point_lots` を持ちます。どの付与分を何pt使ったかを `lot_usages` に残すので、取消のときに元の有効期限で返還できます。
- 操作ごとに担当者名を記録します（スタッフのログイン時に入力）。
- 会員の暗証番号と管理パスワードは PBKDF2-SHA256 でハッシュ化して保存します。会員ログインは5回失敗すると15分ロックします。

## テスト

```sh
python3 -m unittest discover -s tests -t .
```

サーバ版の付与・利用・取消・失効・ランク・画面操作を確認する23件のテストです。画面デモ（`site/`）には自動テストがありません。変更したときは、ブラウザで主な操作（予約 → 催行完了でポイント付与など）を確かめてください。

## 外部サービスについて

- **制度の運用（サーバ版）**：外部サービスを使いません。LINE、クラウドのデータベース、決済サービス、CDN、Web フォントのどれにも接続せず、事務所の PC の中だけで動きます。
- **画面デモ**：GitHub Pages で公開しています。ただし、会員データを外部に送ることはなく、データは見ている人のブラウザの中だけに保存されます。書体も端末に入っているものだけを使います。
- **公開の自動化**：GitHub が提供する公式の Actions（`actions/checkout`、`actions/configure-pages`、`actions/upload-pages-artifact`、`actions/deploy-pages`）だけを使っています。

GitHub Pages は静的なファイルを公開する仕組みで、サーバ側のプログラムは動かせません（出典：[GitHub Docs「About GitHub Pages」](https://docs.github.com/en/pages/getting-started-with-github-pages/about-github-pages)）。そのため、複数の端末で会員データを共有する本番運用には、サーバ版（`points/`）が必要です。
