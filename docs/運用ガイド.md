# 運用ガイド（サービス版）

サービス版（`points/`）を本番で動かすための手順です。会員がスマートフォンから会員アプリを使うには、インターネットから HTTPS でつながるサーバが必要です。

## 全体の形

```
会員のスマホ（会員アプリ /app/） ─┐
                                   ├─ HTTPS ─ Caddy（証明書を自動で取得・更新）─ Python のサーバ（127.0.0.1:8000）─ SQLite ファイル
スタッフの PC（スタッフ画面 /admin）─┘
```

- **会員アプリ**：PWA です。会員はブラウザで `https://ドメイン/app/` を開き、「ホーム画面に追加」するとアイコンから開けます。App Store・Google Play を通さないので、ストアの登録費や審査はありません。
- **スタッフ画面**：`https://ドメイン/admin` を PC のブラウザで開きます。スタッフは1人ずつのアカウントでログインします。
- **データ**：SQLite のファイル1つです。外部のデータベースやクラウドサービスは使いません。

## 用意するもの

| もの | 内容 |
|---|---|
| サーバ | Linux（Ubuntu など）で、Python 3.11 以上が動くもの。VPS やレンタルサーバ。会員数が数千人程度までなら小さなプランで足りる見込みです（要確認） |
| ドメイン | 例：`points.example.jp`。サーバの IP アドレスを DNS に登録します |
| Caddy | HTTPS のリバースプロキシ。ドメインの証明書を自動で取得・更新します |

## 初回の設定

1. サーバに `points` ユーザーを作り、リポジトリを `/opt/earn-points` に置きます。
2. データとバックアップの置き場所を作ります。
   ```sh
   sudo mkdir -p /var/lib/points /var/backups/points
   sudo chown points: /var/lib/points /var/backups/points
   ```
3. [`deploy/points.service`](../deploy/points.service) を `/etc/systemd/system/` に置いて起動します。
   ```sh
   sudo systemctl enable --now points
   sudo journalctl -u points | grep -A1 初回起動
   ```
   初回起動時に管理者アカウント（ログインID `admin`）とパスワードが表示されます。ログインしたら、すぐに「パスワード変更」で変えてください。
4. Caddy を入れ、[`deploy/Caddyfile`](../deploy/Caddyfile) のドメインを書き換えて `/etc/caddy/Caddyfile` に置き、再読み込みします。
5. ブラウザで `https://ドメイン/admin` を開き、ログインできることを確かめます。
6. 「スタッフ管理」で、スタッフ1人ずつのアカウントを作ります。
7. [`deploy/crontab`](../deploy/crontab) を `points` ユーザーの crontab に入れます（毎日の失効処理とバックアップ）。

## 毎日・定期的な作業

| いつ | 何を | どうやって |
|---|---|---|
| 毎日（自動） | 期限切れポイントの失効 | crontab の `python -m points expire` |
| 毎日（自動） | バックアップ | crontab の `python -m points backup ファイル名`。30日分を残します |
| 月1回くらい | バックアップを別の場所にも保存 | サーバが壊れたときのため、`/var/backups/points` の最新ファイルを事務所の PC などにも保存します |
| スタッフが辞めたとき | アカウントの停止 | 「スタッフ管理」で「停止する」 |

## 困ったとき

- **管理者がパスワードを忘れた**：サーバで次を実行します。
  ```sh
  cd /opt/earn-points && sudo -u points POINTS_DB=/var/lib/points/points.sqlite3 python3 -m points staff-password admin
  ```
- **会員が暗証番号を忘れた**：スタッフ画面の会員ページで、本人確認のうえ「暗証番号の再設定」をします。ほかの端末でのログインは解除されます。
- **バックアップから戻す**：サーバを止め（`sudo systemctl stop points`）、バックアップのファイルを `/var/lib/points/points.sqlite3` にコピーしてから起動します。

## 安全のためにしていること

- スタッフも会員も、パスワード・暗証番号はそのまま保存せず、ハッシュ（PBKDF2）にして保存します。
- ログインに5回失敗すると15分ロックします（スタッフ・会員とも）。
- スタッフ画面の操作には、ほかのサイトからの不正な送信を防ぐ合言葉（CSRF トークン）を付けています。会員アプリの API も、ほかのサイトからは送れないようにしています。
- パスワード・暗証番号を変えたり、スタッフを停止したりすると、その人のほかの端末でのログインは解除されます。
- 外部のスクリプトや Web フォントは読み込みません（Content-Security-Policy で禁止）。
- 会員アプリは、電波が弱いところでも会員証を出せるように、最後に見た内容を会員のスマートフォンに保存します。ログアウトすると消えます。

## 本番前に確認すること

- [ ] 会員規約・プライバシーポリシー（[`ポイント規約.md`](ポイント規約.md)）を、会員アプリで個人情報を扱う形に合わせて見直す（法務面は専門家に確認）
- [ ] 道ツアーの招待条件・特典ポイント（今は仮の値）を決めて、「設定」で変える
- [ ] 窓口の受付時間・電話番号を、制度のご案内に入れる
- [ ] バックアップから戻す手順を一度試す

## ストアのアプリにしたくなったら

今の会員アプリ（PWA）を包んで、App Store・Google Play に出すこともできます。ただし、次の点に注意が必要です（2026年11月時点の調べ。最新は各ストアの公式ページで確認してください）。

- 登録費：Apple Developer Program は年99ドル、Google Play は登録時に25ドル（1回のみ）
- Apple の審査では、Web サイトを包んだだけのアプリは「最低限の機能（ガイドライン 4.2）」を理由に却下されやすい。プッシュ通知など、アプリならではの機能を足す必要がある
